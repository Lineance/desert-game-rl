# 训练与调参指南（Stage 1/2/3）

本文是训练专用文档，覆盖三阶段编排、命令示例、关键超参数、日志解读与排障流程。

---

## 1. 训练阶段定义

- Stage 1（手动分离）：Oracle 蒸馏预热（可选），通过 `scripts/pretrain.py` 或 `scripts/train.py --oracle-warmup-episodes` 触发。
- Stage 2（自动化）：生存优先阶段，固定 `alpha`，冻结 `Fund Critic`。
- Stage 3（自动化）：多目标阶段，解冻 `Fund Critic`，`alpha` 从起始值退火到结束值。

> 当前实现中，Stage 1 不额外自动化；Stage 2/3 由 `scripts/train.py` 自动编排（需 `--auto-stages`）。

---

## 2. 快速开始

### 2.1 仅跑基础训练（无自动分阶段）

```bash
uv run python scripts/train.py --level 3 --episodes 2000
```

### 2.2 启用 Stage2/Stage3 自动编排

```bash
uv run python scripts/train.py \
  --level 3 \
  --episodes 3000 \
  --auto-stages \
  --stage2-min-episodes 300 \
  --stage2-success-threshold 0.80 \
  --stage2-entropy-threshold 0.20 \
  --stage2-alpha 0.90 \
  --stage3-alpha-start 0.90 \
  --stage3-alpha-end 0.30 \
  --stage3-alpha-decay-episodes 1200
```

### 2.3 带 Stage1 预热 + Stage2/3 自动编排

```bash
uv run python scripts/train.py \
  --level 4 \
  --episodes 5000 \
  --oracle-warmup-episodes 300 \
  --auto-stages
```

## 3. 关键参数说明

### 3.1 阶段编排参数

- `--auto-stages`
  - 是否启用 Stage2/Stage3 自动化（默认关闭，兼容旧流程）。
- `--stage2-min-episodes`
  - Stage2 最短训练回合，未达到前不会切到 Stage3。
- `--stage2-success-threshold`
  - Stage2→Stage3 切换成功率阈值（基于滚动窗口）。
- `--stage2-entropy-threshold`
  - Stage2→Stage3 切换熵阈值（要求低于该值）。
- `--resume-stage-policy {continue,recompute}`
  - `continue`：从 checkpoint 读取并继续阶段状态。
  - `recompute`：忽略 checkpoint 阶段上下文，重置回 Stage2。

### 3.2 alpha 调度参数

- `--stage2-alpha`
  - Stage2 固定权重（建议 `0.85~0.95`）。
- `--stage3-alpha-start`
  - Stage3 初始权重（通常与 Stage2 接近）。
- `--stage3-alpha-end`
  - Stage3 结束权重（建议 `0.2~0.4`）。
- `--stage3-alpha-decay-episodes`
  - Stage3 线性退火时长（越大越平滑）。

---

## 4. 调参建议

### 4.1 先保生存，再提收益

- 早期全死：提高 `stage2-alpha`（如 `0.95`），并提高 `stage2-min-episodes`。
- 生存稳定但收益低：降低 `stage3-alpha-end`（如 `0.25`），增加 Stage3 时长。

### 4.2 阈值建议

- `stage2-success-threshold`
  - Level 3 可从 `0.75~0.85` 起步。
  - Level 4 可从 `0.65~0.80` 起步。
- `stage2-entropy-threshold`
  - 常用 `0.15~0.25`；过低可能过拟合后才切换，过高可能切换过早。

### 4.3 退火建议

- 若 Stage3 训练波动大：
  - 提高 `stage3-alpha-start`；
  - 增大 `stage3-alpha-decay-episodes`；
  - 减小 `LR_ACTOR`。

## 5. 日志与指标解读

训练 CSV/TensorBoard 重点关注：

- `alpha_mean`
  - 当前价值损失中生存权重均值。
- `survival_value_loss`
  - 生存 critic 误差；若长期高位，Stage2 阈值可能过严或学习率过大。
- `fund_value_loss`
  - 资金 critic 误差；Stage3 解冻后短期上升属常见现象。
- `stage_name`
  - 当前阶段（`default/stage2/stage3`）。
- `stage_transition`
  - 是否发生阶段切换事件。

## 6. 续训与复现

### 6.1 续训命令

```bash
uv run python scripts/train.py --level 3 --episodes 3000 --resume latest --auto-stages
```

### 6.2 续训策略

- 推荐默认：`--resume-stage-policy continue`。
- 若怀疑阶段上下文损坏或策略漂移：用 `recompute` 回到 Stage2 重启阶段编排。

### 6.3 复现建议

- 固定 `--level`、`--episodes`、阶段参数与 `weather-mode`。
- 保留 `artifacts/checkpoints/level*_latest.pt` 与 `artifacts/results/*_train_metrics.csv`。

---

## 7. 常见问题排障

- 切不到 Stage3：
  - 降低 `stage2-success-threshold` 或放宽 `stage2-entropy-threshold`。
- 切换后收益下降：
  - 提高 `stage3-alpha-start`，延长 `stage3-alpha-decay-episodes`。
- 训练震荡明显：
  - 降低学习率，或提高 `stage2-min-episodes` 先稳定生存策略。
- 恢复训练后阶段异常：
  - 检查 `resume-stage-policy` 是否符合预期。
